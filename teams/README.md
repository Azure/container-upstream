# Teams

The [project list](../README.md#project-list) catalogs *what* the Azure Core
Container Upstream team works on. These pages map the same ground the other way —
*who* works on each project, so you can find the right people for a given repo.

Project facts (goal, maturity, communication channels, Azure usage) live in the
project list and are not repeated here. These pages contain only handle-to-project
links.

| Team | Focus | Page |
|------|-------|------|
| Observability | eBPF-based runtime observability and debugging | [observability.md](observability.md) |
| DevX | Developer-facing Kubernetes tooling — UIs, editor extensions, CI actions | [devx.md](devx.md) |
| Networking | Service mesh, proxies, and gateway APIs | [networking.md](networking.md) |

## Conventions

- **Handles, not names.** Every handle listed is already visible in the public
  commit history of the repo it appears next to.
- **Reach people through project channels** — issues, PRs, or the project's Slack
  or Discord as listed in the [project list](../README.md#project-list) — rather
  than direct messages. These pages are not a support channel; see
  [Support](../README.md#support).
- **Ordered by contribution volume**, most active first. That is a rough activity
  signal, not a statement of ownership, seniority, or maintainer status.
- **Upstream repos only.** Personal forks used for PR branches are omitted, as are
  occasional and one-off contributions.
- **Contributor, not owner.** Listing a project here means people on the team
  contribute to it. Several of these projects are governed by CNCF, the Linux
  Foundation, or another vendor entirely.

## Maintenance

Membership drifts. Refresh from public commit history and contributor lists when a
team changes, and open a PR. Do not treat a stale page as authoritative for
escalation or on-call.
